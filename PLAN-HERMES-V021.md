### Comment font Hermes Setup et Hermes Desktop (lu le 18/10, v0.22.2, par un sous-agent ; trois points revérifiés à la main)

- **Hermes Setup** (`/Applications/Hermes.app` ici, `apps/bootstrap-installer`) : télécharge `install.sh` de `main` à chaque lancement (`install_script.rs:101-105`), lit `--manifest`, puis lance chaque étape avec `-Stage <nom> -NonInteractive -Json` (+ `-IncludeDesktop`) (`bootstrap.rs:712-721`, revérifié), lit la dernière ligne JSON de chaque étape et montre les titres d'étape, avec le journal derrière « Show details » ; une étape peut être relancée 3 fois si le processus meurt. Jamais `--skip-browser` ni `--skip-computer-use` (Desktop installe Chromium et cua-driver), pas de `--channel` (donc le défaut `stable`). Aucun service gateway, aucune écriture de `API_SERVER_*` ni de clé. Écran d'accueil sans choix (« Install »), échec → « Retry install » / « Open logs », succès → « Launch » ouvre Desktop. Pour les Command Line Tools, il compte sur le script de `main` (attente en mode `--json`, #2 et #6).
- **Hermes Desktop, premier lancement** : l'essai gratuit est réclamé **sans clic** (`onboarding.start`, `tui_gateway/methods_onboarding.py:126-171`), puis une conversation guidée (prénom, couleur, disposition, apps, extensions, visite, première tâche), chaque carte passable, « Skip setup » pour tout passer. Connexion Nous par code d'appareil via le tableau de bord (`POST /api/providers/oauth/nous/start` puis `…/poll/{sid}`, `hermes_cli/web_routers/oauth.py`), **pas servi par le gateway** de NotchNotch. Confidentialité : seulement un bandeau « Terms of Service and Privacy Policy » pour l'essai ; rien sur la conservation chez le fournisseur.
- **Contrôle du Mac dans Desktop** : hors premier lancement, dans Capabilities › Toolsets. L'activer écrit `platform_toolsets.cli` (celui que lisent les sessions Desktop, `web_routers/tools.py:280-308`, revérifié) et installe le pilote par `hermes tools post-setup cua_driver` ; les droits par `hermes computer-use permissions grant`.
